# 뉴욕시 311 민원 데이터 — 컬럼 설명

`data/raw/nyc311/` 폴더의 CSV 파일 설명입니다.

> 아래 "컬럼별 상세 설명"의 건수·비율은 **2024-10 ~ 2026-10 (323,670건)** 기준으로 처음 집계한 값입니다. 10년치 연도별 건수와 주의점은 `data/processed/README.md`를 보세요.

## 데이터 개요

| 항목 | 내용 |
|---|---|
| 출처 | NYC Open Data — 311 Service Requests. 2019년까지 `76ig-c548`(2010 to 2019), 2020년부터 `erm2-nwe9`(2020 to Present) |
| 받는 방법 | `pipelines/fetch_nyc311.py` (필요한 17개 컬럼만 받음, 달마다 알맞은 데이터셋 자동 선택) |
| 지역 | 브롱크스(BRONX) 자치구만 |
| 기관 | 8곳 (경찰 NYPD, 주택 HPD 등은 제외). 2019년 이전 소비자보호국 약어는 `DCA` |
| 기간 | 접수일 기준 2016-01-01 ~ 2026-10-12 |
| 건수 | 1,546,798건, 17개 컬럼 |
| 인코딩·형식 | UTF-8 CSV, 날짜는 `YYYY-MM-DDTHH:MM:SS.000` (뉴욕 현지 시각) |

### 파일 구성

| 파일 | 내용 |
|---|---|
| `nyc311_YYYY-MM.csv` (130개) | 월별 파일. 2026-10은 12일까지만 |

> 하나로 합친 파일이 필요하면 `python pipelines/fetch_nyc311.py --start 2016-01-01 --end 2026-10-13 --borough BRONX --agency DSNY DEP DOT DOB DOHMH DPR DCWP DCA DHS --combine`로 만들 수 있습니다(이미 받은 달은 건너뜀). 병합 스크립트는 월별 폴더를 그대로 읽습니다.

## 컬럼별 상세 설명

### 1. `unique_key` — 민원 번호
- 311에 들어온 민원(서비스 요청) 한 건마다 붙는 고유 번호입니다. 중복 없음(323,670개 모두 다름).
- 숫자지만 계산에 쓰지 않으므로 문자로 읽는 것을 권장합니다.

### 2. `created_date` — 접수일시
- 민원이 311 시스템에 등록된 날짜와 시각입니다.
- 범위: 2024-10-01 00:06 ~ 2026-10-10 00:26
- 주간 접수 건수 예측의 기준 날짜입니다. 마지막 주(2026-10-05 주)는 일부만 들어 있어 학습·평가에서 빼야 합니다.

### 3. `closed_date` — 처리완료(종결)일시
- 담당 기관이 민원을 종결 처리한 날짜와 시각입니다. 처리 중인 민원은 비어 있습니다(11,719건, 3.6%).
- **처리기간 = `closed_date` − `created_date`** 로 계산합니다.
- 주의할 값
  - 처리완료일시가 접수일시보다 빠른 건: 449건 → 오류로 보고 제외
  - 접수 후 1분 안에 종결된 건: 28,107건 → 즉시 안내·이관 등으로 보이며, 처리기간 분석에서는 따로 구분
  - 시각이 00:00:00인 건: 약 12% → 날짜만 기록된 경우라 처리기간은 일 단위로 보는 것이 안전

### 4. `due_date` — 처리기한(갱신 예정일)
- 원래 뜻은 "담당 기관이 이 민원의 처리 상황을 갱신해야 하는 예정일"로, 민원 유형별 내부 기준(SLA)에 따라 정해집니다. 국내의 법정처리기한과 비슷한 개념입니다.
- 이 데이터에서는 **3,546건(1.1%)에만 값이 있고, 모두 위생국(DSNY)의 낙서(Graffiti) 민원**입니다.
- 그래서 프로젝트에서는 이 컬럼 대신 **민원 유형별 과거 처리기간의 90번째 백분위수(P90)** 를 기준처리기간으로 씁니다.

### 5. `resolution_action_updated_date` — 최종 처리조치 갱신일시
- 담당 기관이 이 민원에 대해 마지막으로 처리 내용을 갱신한 날짜와 시각입니다.
- 처리 중인 민원이 마지막으로 언제 손을 탔는지 볼 때 쓸 수 있습니다.
- 주의: 8,562건은 접수일시보다 앞선 날짜(가장 이른 값 2022-09-21)가 들어 있습니다. 같은 장소의 이전 민원과 합쳐 처리된 경우 등으로 보이며, 사용 시 걸러야 합니다.

### 6. `status` — 처리 상태

| 값 | 뜻 | 건수 |
|---|---|---|
| Closed | 처리완료(종결) | 310,380 |
| In Progress | 처리 중 | 8,107 |
| Open | 접수됨(아직 착수 전) | 2,520 |
| Assigned | 담당자(팀) 배정됨 | 1,532 |
| Pending | 보류(추가 정보·다른 기관 회신 대기 등) | 795 |
| Started | 착수함 | 326 |
| Unspecified | 미지정 | 10 |

- 프로젝트에서는 `Closed`를 **처리완료**, 나머지를 **처리 중(미처리)** 으로 묶어 씁니다.
- 기관마다 쓰는 상태값이 다릅니다 (예: `Started`는 환경보호국만 사용).

### 9. `complaint_type` — 민원 유형
- 민원의 큰 분류입니다(137종). 예: `Water System`(상수도), `Noise`(소음), `Rodent`(쥐), `Elevator`(승강기), `Street Condition`(도로 상태), `Illegal Dumping`(불법 투기).
- 같은 유형이라도 기관에 따라 처리 방식이 다를 수 있어, 기준처리기간은 **기관 + 유형** 조합으로 계산하는 것을 권장합니다.

### 10. `descriptor` — 민원 세부 유형
- `complaint_type` 아래의 세부 내용입니다(779종). 예: `Water System` → `Fire Hydrant Emergency (FHE)`(소화전 무단 개방), `Rodent` → `Rat Sighting`(쥐 목격).
- 2,317건(0.7%)이 비어 있습니다.
- 참고: 2025-06-23 주에 접수가 9,151건으로 평소의 3배였는데, 그중 4,562건이 `Fire Hydrant Emergency (FHE)`였습니다(폭염 때 소화전을 여는 일).

### 11. `location_type` — 장소 유형
- 민원이 발생한 장소의 종류입니다(126종). 예: `Street`(도로), `Sidewalk`(보도), `Park`(공원), `3+ Family Apt. Building`(3세대 이상 공동주택), `Business`(사업장).
- **43.5%가 비어 있습니다.** 유형에 따라 아예 입력받지 않는 경우가 많으므로 결측을 "미기재" 범주로 두고 씁니다.
- 같은 뜻인데 표기가 다른 값이 있습니다 (예: `3+ Family Apt. Building`과 `3+ Family Apartment Building`). 합쳐서 정리해야 합니다.

### 12. `open_data_channel_type` — 접수 채널

| 값 | 뜻 | 건수 |
|---|---|---|
| PHONE | 전화(311 콜센터) | 108,941 |
| ONLINE | 웹사이트 | 92,176 |
| UNKNOWN | 알 수 없음 | 86,476 |
| MOBILE | 모바일 앱 | 35,822 |
| OTHER | 기타(문자, 다른 기관 이관 등) | 255 |

- `UNKNOWN`이 27%로 많습니다. 결측으로 버리지 말고 하나의 범주로 둡니다.

### 13. `borough` — 자치구
- 뉴욕시 5개 자치구(맨해튼·브루클린·퀸스·브롱크스·스태튼아일랜드) 중 하나입니다.
- 이 데이터는 브롱크스만 받았으므로 **모든 값이 BRONX**입니다.

### 14. `community_board` — 커뮤니티 보드
- 자치구 아래의 주민자치 구역입니다(우리나라의 행정동 묶음과 비슷). 형식은 `번호 자치구명`입니다.
- `01 BRONX` ~ `12 BRONX`: 브롱크스의 12개 커뮤니티 보드
- `26 BRONX`, `27 BRONX`, `28 BRONX`: 어느 보드에도 속하지 않는 대형 공원 등 공동관할구역(JIA)
- `Unspecified BRONX`: 구역 미지정(7,022건)
- `01 QUEENS`: 7건 — 브롱크스 데이터에 섞인 이상값

### 15. `incident_zip` — 발생지 우편번호
- 민원 발생 장소의 우편번호(5자리)입니다. 브롱크스 우편번호 24종이 들어 있고 2.0%가 비어 있습니다.
- 앞자리 0이 있을 수 있는 다른 지역 데이터와 합칠 때를 대비해 **문자로 읽습니다**.

### 16. `latitude` — 위도 / 17. `longitude` — 경도
- 민원 발생 장소의 좌표(WGS84, 일반 지도 좌표)입니다. 4.5%가 비어 있습니다.
- 위도 40.79 ~ 40.91, 경도 −73.93 ~ −73.77 범위로 모두 브롱크스 안입니다.

## 프로젝트 용어와의 연결

| 프로젝트 용어 | 이 데이터에서 |
|---|---|
| 접수일 | `created_date` |
| 처리일(종결일) | `closed_date` |
| 처리기간 | `closed_date − created_date` (일) |
| 처리부서 | `agency` |
| 민원 유형 | `complaint_type` (+ `descriptor`) |
| 처리 상태 | `status` (`Closed` = 완료, 나머지 = 처리 중) |
| 법정처리기한 | 없음 → 유형별 처리기간 P90으로 대체 |
| 접수 경로 | `open_data_channel_type` |
| 지역 | `community_board`, `incident_zip`, 위도·경도 |

## 읽기 예시 (pandas)

```python
import pandas as pd

df = pd.read_csv(
    "data/raw/nyc311/nyc311_20241001_20261013.csv",
    dtype={"unique_key": str, "incident_zip": str},
    parse_dates=["created_date", "closed_date", "due_date", "resolution_action_updated_date"],
)
df["proc_days"] = (df["closed_date"] - df["created_date"]).dt.total_seconds() / 86400
df["is_open"] = df["status"] != "Closed"
```
