## 1. 서비스 한 줄 정의
민원 부서별로 기간을 선택하면 그 기간의 **민원 집중도(예상 건수·예상 이슈·위험도)** 를 미리 보여 주고, 집중도가 높은 부서에 **인력을 연결**하도록 돕는 행정 지원 대시보드.

## 2. 확정된 결정
| 항목 | 결정 | 근거 |
|---|---|---|
| 목적 | **전무님 평가용 시연 중심**, 기관(폐쇄망) 이관은 나중 | 사용자 결정 |
| 프런트엔드 | **React + TypeScript** + ECharts (파일 포함, 오프라인 동작) | 사용자 React 경험 있음. 부서·기간 선택이 여러 차트에 연동됨 |
| 백엔드 | FastAPI (Python) | 모델이 전부 Python, 자동 API 문서로 연동성 시연 |
| Python 환경 | uv + Python 3.12 (구성 완료) | 시스템 3.9는 지원 종료 |
| 데이터 저장 | Parquet + DuckDB | PC 메모리 8GB, 10년치 약 160만 건 |
| 모델 | scikit-learn, LightGBM(macOS는 libomp 필요), statsmodels, lifelines, scipy | 기획서 기법 그대로 |
| 결과 제공 | 시연용은 미리 계산해 저장 | 시연 중 지연·오류 방지 |

## 3. 화면 구성 (수정안)
### 상단
- 부서 선택, 날짜 기간 선택
- 빠른 선택: **다음 한 달, 다음 분기**

### 중앙 (메인)
1. **선택 기간 예상 민원 건수** 차트 (예측 구간 포함)
2. **예상 이슈 키워드** (결빙, 폭염, 수돗물 등)
3. **2×2 위험 매트릭스** (선택 기간 기준)

### 기간별 예측 근거 (기상 예보 15일 한계 대응)
| 선택 기간 | 건수 예측 근거 | 이슈 키워드 근거 | 화면 표현 |
|---|---|---|---|
| 1~7일 | 최근 추세 + 기상 예보 | 예보 (예: "3일 뒤 폭우 → 침수·수목 민원 집중") | 건수 + 신뢰구간 |
| 8~16일 | 최근 추세 + 예보·평년값 혼합 | 예보 경향 + 과거 빈도 | 넓은 범위 |
| 16일 이후 (한 달·분기) | **계절 지수 × 최근 수준** + 80% 범위 | 과거 빈도를 확률로 (예: "결빙 급증 가능성 67%, 최근 9년 중 6년"), 도로 파손은 겨울 적설 기반 | 건수 + 범위 |

### 시연용 제안 기능: 과거 시점 재현 모드
기준일을 과거로 돌려 "그때 이 시스템이 있었다면 미리 알렸을까"를 보여 줌.
- 예: 2026-02-20 기준 → 블리자드 예보로 위생국 경보 → 실제 2/24 제설 민원 3.6배
- 필요: Open-Meteo 과거 시점 예보 기록(Historical Forecast API). 범위 확인 필요

## 4. 2×2 위험 매트릭스 정의
| 요소 | 정의 |
|---|---|
| 가로축 (접수 증가율) | 선택 기간 일평균 예측 건수 ÷ **최근 4주 일평균** − 1 ("지금 인력 기준으로 얼마나 더 몰리나") |
| 세로축 (장기처리 위험) | 단기(1~2주): 처리 중 민원의 건별 위험 확률 평균 / 한 달·분기: **예상 유형 구성 × 유형별 과거 장기처리율** ("구조적 위험" 표기) |
| 원 크기 | 단기: 현재 처리 중 건수 / 장기: 기간 예상 접수 건수 |
| 사분면 기준 (예시 화면) | 가로 +10%, 세로 25% → 오른쪽 위 "집중관리", 왼쪽 위 "처리지연 주의", 오른쪽 아래 "접수증가 주의" |
| 부서명 | 뉴욕 8개 기관 → 국내 부서명 대응표 필요 (예: DSNY→자원순환·청소, DOT→도로·교통, DPR→공원녹지, DOB→건축, DEP→상하수도·환경) |

**장기처리(위험) 민원 정의:** 부서별 처리기간 P90 초과. P90은 매달 6~12개월 전 데이터로 다시 계산. 처리 중 민원은 중도절단으로 반영(기준 경과 시 위험=1, 미경과는 학습 제외). "30일 초과"는 보조 지표.

## 5. 인력 연결
- 데이터로 계산 가능한 범위: 부서별 **추가 처리 필요 건수** = (예상 건수 − 평소 처리능력), 여유 부서의 남는 처리능력과 매칭(수송 문제, scipy linprog)
- "명" 단위 환산: **부서 인원 또는 1인당 처리량 가정값이 필요** (뉴욕 데이터에 없음) → 화면에서 가정값 입력받는 방식 검토

## 6. 이슈 키워드 묶음과 검증된 기상 관계 (2024-10 ~ 2026-10 기준)
| 이슈 | 매칭 규칙 | 관련 기상 → 관련 민원 배수 |
|---|---|---|
| 폭염·소화전 | 세부 유형에 Hydrant | 최고 ≥ 32°C 당일 22.5배 |
| 수돗물 | No Water, Dirty Water, Low Water Pressure, Water Main Break | 최고 ≥ 32°C 당일 5.7배 |
| 결빙·제설 | 유형 Snow / Snow or Ice | 적설 ≥ 2cm, **1~2일 뒤** 17~18배 |
| 폭우·침수 | Sewer Backup, Catch Basin, Flooding | 강수 ≥ 25mm 당일 2.9배 |
| 강풍·수목 | 유형 Damaged Tree | 강수 ≥ 25mm 당일 4.1배 (강풍은 돌풍 변수 사용) |
| 도로 파손 | Pothole, Cave-in | **겨울 적설 합계 → 3~4월 급증** (10개 겨울 순위상관 0.94, 2025/26 겨울 77.7cm → 5.8배) |
| 쥐 / 보일러 / 가로등 | Rodent / Boilers / Street Light Out | 계절성 |

## 7. 데이터
| 데이터 | 범위 | 위치 | 비고 |
|---|---|---|---|
| 뉴욕 311 민원 | 브롱크스, 8개 기관, 2016-01 ~ 2026-10-12 | `data/raw/nyc311/` (월별 130개) | 2019년까지 `76ig-c548`, 2020년부터 `erm2-nwe9`. 2019년 이전 소비자보호국 `DCA` → `DCWP`로 통일 |
| Open-Meteo 과거 관측 | 2016-01-01 ~ 2026-10-13, 일 단위 | `data/raw/weather/` | 격자점 40.808, -73.892. `timezone=America/New_York` |
| 병합 결과 | 날짜별 기상 변수, 날짜×기관, 날짜×이슈, 민원 1건별 | `data/processed/` | 병합 키 = 접수일의 뉴욕 현지 날짜, 1~3일 지연 변수 포함 |

스크립트: `pipelines/` (`fetch_nyc311.py`, `fetch_openmeteo.py`, `merge_weather.py`). 병합은 월별 폴더를 그대로 읽음.

**데이터 주의점**
- 민원 유형 이름이 해마다 다름 (예: `Snow` → `Snow or Ice`). 위생국은 2019년 이전에만 있던 요청 유형(대형 폐기물 수거 등)이 있어 연도별 단순 비교 금지
- 2020~2021년은 코로나 영향으로 패턴이 다를 수 있음
- Open-Meteo 무료 API는 비상업용. 상용 운영 시 유료 키 필요

## 8. 실현 가능성 (2년치 검증, 한 달·분기는 10년치로 갱신)
| 항목 | 판정 | 비고 |
|---|---|---|
| 부서·기간 선택 | 가능 | |
| 단기 예상 건수·이슈 (기상 연동) | **가능** | 가장 강한 근거 |
| 한 달·분기 예상 건수 | **가능 (10년치 검증)** | 계절 지수 × 최근 수준: 한 달 오차 평균 14%(부서별 7~26%), 분기 12%. 80% 범위 포함률 70~89%. 환경보호국·공원국·노숙자서비스국은 범위 중심 표시 |
| 한 달·분기 예상 이슈 | **가능 (10년치 검증)** | 과거 빈도가 확률처럼 맞음(빈도 70%↑ → 실제 73%). 폭염·결빙·보일러는 달력, 수목·수돗물은 단기 예보로만, 도로 파손은 겨울 적설로 예측 |
| 매트릭스 가로축 | 가능 | |
| 매트릭스 세로축 (장기) | 조건부 | 유형 구성 방식 오차 6.1%p, 부서 순위 상관 0.51 |
| 인력 "명" 단위 | 인원 자료 필요 | |
